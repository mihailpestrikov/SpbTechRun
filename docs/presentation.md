## Слайд 13: Как работает ML — Эмбеддинги

**Заголовок:** Эмбеддинги товаров

**Текст для озвучивания:**

> Как система понимает, что товары похожи? Мы используем эмбеддинги — векторные представления товаров. Для каждого товара формируем текст: название, категория, бренд, параметры. Этот текст передаём в модель Ollama nomic-embed-text, которая возвращает вектор из 768 чисел. Похожие товары имеют близкие векторы.

**Пример на слайде:**

```
Текст товара:
"Грунтовка KNAUF Tiefengrund 10л.
Категория: Грунтовки для внутренних работ.
Бренд: KNAUF. Объём: 10 литров."

       ↓ Ollama (nomic-embed-text)

Вектор: [0.123, -0.456, 0.789, ... ] (768 чисел)
```

**Визуал:** Схема: Текст → Модель → Вектор

## Слайд 14: Как работает ML — Двухуровневое ранжирование

**Заголовок:** FAISS + CatBoost: двухуровневая архитектура

**Текст для озвучивания:**

> Система использует двухуровневую архитектуру ранжирования. На первом уровне FAISS быстро отбирает топ-100 кандидатов по семантической близости эмбеддингов. На втором уровне CatBoost Ranker переранжирует кандидатов на основе 44 признаков: семантика, фидбек, цены, категории, совместные покупки, и комплементарность. Это даёт и скорость, и точность.

**Схема на слайде:**

```
100k товаров
     ↓ FAISS (< 5ms)
100 кандидатов
     ↓ CatBoost (44 признака)
20 рекомендаций
```

**44 признака CatBoost:**

| Группа | Признаки |
|--------|----------|
| Семантические (6) | cosine_similarity, l2_distance, dot_product... |
| Фидбек (8) | pair_positive, pair_negative, pair_approval... |
| Ценовые (7) | price_ratio, discount_percent, price_diff... |
| Категорийные (5) | same_category, same_root, category_distance... |
| Co-purchase (3) | copurchase_count, copurchase_exists... |
| Популярность (7) | view_count, cart_add_count, order_count... |
| Контекст корзины (3) | cart_similarity_max, cart_similarity_avg... |
| **Комплементарность (5)** | complementarity_score, category_semantic_similarity... |

**Визуал:** Схема двухуровневого ранжирования

## Слайд 15: Модель комплементарности категорий

**Заголовок:** ML-модель для cross-category рекомендаций

**Текст для озвучивания:**

> Базовые признаки хорошо работают для товаров из одной категории, но плохо рекомендуют комплементарные товары из других категорий. Например, для штукатурки нужны шпатели и правила, но это другие категории. Мы обучили отдельную LogisticRegression модель на 300+ размеченных парах категорий. Модель вычисляет эмбеддинги категорий — среднее эмбеддингов всех товаров в категории — и предсказывает вероятность комплементарности. 5 новых признаков добавлены в CatBoost: скор модели, семантическое сходство категорий, связь через сценарии, и агрегированные co-purchase на уровне категорий.

**Схема на слайде:**

```
Штукатурка (категория 25178)
           ↓
Вычисляем эмбеддинг категории (среднее по товарам)
           ↓
LogisticRegression модель
           ↓
Комплементарные категории:
  ✓ Шпатели (95%)
  ✓ Грунтовки (92%)
  ✓ Правила (89%)
  ✓ Ёмкости (87%)
```

**Примеры на слайде:**

| Основная категория | Комплементарные категории | Score |
|-------------------|---------------------------|-------|
| Штукатурка | → Шпатели, Правила, Грунтовки | 90%+ |
| Плитка | → Клей, Затирка, Крестики | 85%+ |
| Наливной пол | → Валики, Миксеры, Грунт | 90%+ |

**Визуал:** Схема работы модели комплементарности с примерами

## Слайд 17: Байесовское сглаживание

**Заголовок:** Защита от шума в данных

**Текст для озвучивания:**

> Чтобы один случайный лайк не давал 100% рейтинг, используем байесовское сглаживание. Формула добавляет виртуальный голос "за" и "против". Новый товар без статистики получает 50%. Товар с 10 лайками — примерно 85%, а не 100%.

**Формула на слайде:**

```
approval = (positive + 1) / (total + 2)
```

**Таблица примеров:**

| Лайки | Дизлайки | Обычный % | С Байесом |
|-------|----------|-----------|-----------|
| 0 | 0 | - | 50% |
| 10 | 0 | 100% | 85% |
| 5 | 5 | 50% | 50% |
| 0 | 10 | 0% | 8% |

## Возможные вопросы жюри

**Q: Почему выбрали nomic-embed-text, а не другую модель?**
> A: Это одна из лучших open-source моделей для эмбеддингов на русском языке. Размер 768 измерений — оптимальный баланс между качеством и скоростью. Работает локально через Ollama.

**Q: Почему CatBoost, а не нейросеть?**
> A: Для табличных данных (44 признака) градиентный бустинг работает лучше нейросетей. CatBoost специально оптимизирован для learning-to-rank задач (YetiRank loss). Быстрое обучение (~2 минуты) и inference (~50ms).

**Q: Как система ведёт себя на холодном старте?**
> A: При отсутствии фидбека и обученной модели используется fallback-формула на эмбеддингах. Качество приемлемое (~60%), улучшается по мере накопления данных. После 100+ оценок переобучаем CatBoost.

**Q: Как часто нужно переобучать CatBoost?**
> A: Рекомендуем раз в неделю или после накопления 100+ новых оценок фидбека. Переобучение занимает ~2 минуты через API endpoint.

**Q: Сколько времени занимает генерация эмбеддингов?**
> A: Для 60k товаров — около 60 минут на CPU. Делается один раз, потом эмбеддинги можно экспортировать и использовать без Ollama.

**Q: Как масштабируется система?**
> A: ML-сервис stateless — можно запустить несколько инстансов за load balancer. FAISS работает в памяти, для миллионов товаров можно использовать IVF-индекс или Milvus.

**Q: Почему не использовали готовые рекомендательные системы?**
> A: Требование закрытого контура исключает облачные решения. Мы построили кастомное решение, заточенное под специфику строительных товаров и сценарии ремонта.

**Q: Какие признаки самые важные в CatBoost?**
> A: По feature importance: complementarity_score, cosine_similarity, pair_approval (фидбек), copurchase_count, same_category, price_ratio. Можно посмотреть через API `/ml/model-info`.

**Q: Что такое модель комплементарности категорий?**
> A: Отдельная LogisticRegression модель, обученная на 300+ размеченных парах категорий (штукатурка → шпатели, плитка → клей). Вычисляет эмбеддинги категорий как среднее эмбеддингов товаров и предсказывает вероятность комплементарности. Добавляет 5 новых признаков в CatBoost для улучшения cross-category рекомендаций. Обучается командой: `docker exec spbtechrun-recommendations-1 python -m app.train_complementarity`
